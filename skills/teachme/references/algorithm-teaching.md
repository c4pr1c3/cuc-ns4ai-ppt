# 算法讲解特化指南

针对算法和数据结构讲授场景的补充指南。与通用工作流配合使用。

## 算法讲解的"血肉"增强

### 1. 动机：为什么需要这个算法？

不要只说"这是一个排序算法"。要说：
- 在什么场景下，现有方法（如简单遍历、暴力搜索）会失败？
- 数据规模或约束条件如何催生了这个算法？
- 这个算法解决了哪一类更通用的问题？

**示例**：
> 不是"KMP 是一个字符串匹配算法"，而是"当需要在 1GB 的日志文件中搜索一个 100 字节的关键词时，暴力匹配的 O(nm) 复杂度会让查询耗时数秒。KMP 通过利用已匹配信息避免回退，将复杂度降到 O(n+m)，让日志分析从'可接受'变成'实时'。"

### 2. 直觉：算法在"做什么"？

用可视化、类比或简化案例建立直觉，再进入形式化描述。

**技巧**：
- **边界游走法**：手动走一遍最小非平凡示例，画出状态变化
- **不变式直觉**：找出算法维持的核心不变式，用一句话概括
- **类比法**：将算法与日常经验类比（例如：并查集 = "朋友圈合并"）

**示例**：
> 讲解 Dijkstra 时，不说"维护一个优先队列，每次取最短距离节点松弛边"，而说"就像水从源点慢慢漫延，先到达的地方一定是最短路径——因为如果有更短的路，水应该早就从那条路流过来了"。

### 3. 弯路：从朴素到优雅的演进

展示算法的"前身"和为什么它们不够：
- 暴力解法是什么？复杂度如何？瓶颈在哪里？
- 第一个改进尝试是什么？解决了什么，又引入了什么新问题？
- 最终的洞察是什么？如何一次性解决所有问题？

**示例**：
> 最短路径：暴力枚举所有路径 → Bellman-Ford（动态规划思想，可处理负权但慢） → Dijkstra（贪心+优先队列，正权图最优） → A*（加入启发式，针对目标搜索优化）。每一步的取舍都很清晰。

### 4. 形式化：在直觉之上的精确

直觉建立后，给出形式化描述：
- 输入/输出规范
- 算法步骤（伪代码或代码）
- 正确性证明的核心思路（可选，视受众而定）
- 复杂度分析（时间 + 空间，最好、平均、最坏情况）

**注意**：形式化描述中的每一行都应该能和直觉对应上。如果直觉中说"水慢慢漫延"，形式化中的"优先队列取最小距离节点"就是"水先到达距离最短的地方"。

### 5. 代码实例：从伪代码到生产代码

- 先给出清晰的伪代码（聚焦思想）
- 再给出实际可运行的代码（聚焦实现细节）
- 如果仓库中有相关实现，优先使用仓库代码并逐行注释

**代码讲解要点**：
- 每行关键代码对应算法步骤中的哪一步？
- 初始化在做什么？（建立不变式）
- 循环不变式是什么？（每次迭代保证什么）
- 终止条件为什么正确？

### 6. 常见误区清单

| 误区 | 正确理解 |
|------|----------|
| Dijkstra 能处理负权边 | Dijkstra 的贪心性质依赖非负权重，负权边会破坏正确性 |
| 快速排序总是 O(n log n) | 最坏 O(n²)，虽然随机化后期望是 O(n log n) |
| 二分查找很简单，一看就会 | 边界条件（left < right vs left <= right）是面试高频坑点 |
| 哈希表查询是 O(1) | 是平均 O(1)，最坏 O(n)；且哈希冲突处理有多种策略 |
| DFS 和 BFS 只是实现方式不同 | 它们解决的性质完全不同：DFS 找路径/连通性，BFS 找最短路径 |

### 7. 延伸：与其他算法的联系

- 这个算法是哪些更通用框架的特例？（例如 Dijkstra = 贪心 + BFS + 优先队列）
- 它与哪些算法形成"对偶"或"互补"？（例如 Prim vs Kruskal，DFS vs BFS）
- 在实际工程中，它通常和哪些技术组合使用？

## 算法可视化建议

如果输出支持可视化（如 huashu-design 幻灯片），建议包含：
- 算法执行过程的逐步动画（最小示例）
- 状态变化图（搜索树、图遍历的访问顺序）
- 复杂度对比图（与朴素算法的性能差异）
