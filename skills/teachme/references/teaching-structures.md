# 教学结构模板库

根据主题特性、受众水平和时间约束，从以下四种结构中选择最合适的一种。

## 问题导向式（Problem-First）

**适用场景**：算法讲解、概念引入、协议设计原理
**核心思想**：从"要解决什么问题"出发，让受众感受到"痛点"，再自然引出解决方案。

**结构框架**：

```
1. 问题呈现（5%）
   - 一个具体、可感知的问题场景
   - 让受众产生"这确实是个问题"的共鸣

2. 朴素尝试（15%）
   - 最直观的解决方案是什么？
   - 分析朴素方案的局限（时间/空间/正确性）
   - 让受众理解"为什么简单方法不够"

3. 关键洞察（20%）
   - 突破朴素方案局限的核心思想是什么？
   - 用类比或图像建立直觉
   - "如果我们换个角度看问题..."

4. 形式化方案（35%）
   - 基于关键洞察，给出精确的定义/算法/协议
   - 逐步推导，每一步都说明"为什么这样做"
   - 复杂度分析或正确性论证

5. 实际应用（15%）
   - 真实代码示例
   - 工程实践中的变体和优化

6. 常见误区与总结（10%）
   - 最容易掉进的坑
   - 核心 takeaway
```

**示例**：
- 讲解一致性哈希：从"传统哈希在节点增减时大规模数据迁移"的问题 → 朴素重哈希 → 环形空间和虚拟节点洞察 → 一致性哈希算法 → Redis Cluster 中的应用 → 热点问题误区

## 认知负荷分层式（Cognitive Load Layering）

**适用场景**：复杂系统架构、分布式协议、编译器/内核等深度技术主题
**核心思想**：按认知负荷分层，先给大图景建立 mental model，再逐步填充细节。

**结构框架**：

```
1. 大图景/直觉层（10%）
   - 一句话概括：这个系统/协议是做什么的？
   - 类比：用日常事物类比核心机制
   - 核心组件的交互图景（一张架构图）

2. 核心机制层（50%）
   - 系统的主要组成部分及其职责
   - 关键交互流程（用序列图或流程图）
   - 核心设计决策及其理由
   - 每个机制先讲"做什么"，再讲"怎么做"

3. 边界与细节层（25%）
   - 异常处理路径
   - 性能优化细节
   - 配置参数和调优策略
   - 与相关系统的集成方式

4. 误区与总结层（15%）
   - 常见误解（大图景层的错误认知）
   - 细节层的陷阱（配置错误、边界条件）
   - 核心 takeaway + 进一步学习路径
```

**示例**：
- 讲解 Raft 共识协议：先讲"分布式系统如何在机器故障时保持一致"的大图景 → Leader 选举 + 日志复制的核心机制 → 网络分区处理、日志压缩等边界细节 → "Raft 不是万能的"误区

## 对比分析式（Comparative Analysis）

**适用场景**：技术方案选型、算法选择、架构模式对比
**核心思想**：通过多维度对比，让受众理解"没有银弹"，每种方案有其适用场景。

**结构框架**：

```
1. 问题与约束（10%）
   - 要解决的核心问题
   - 硬性约束（性能、成本、安全、合规）
   - 软性约束（团队熟悉度、生态、维护成本）

2. 候选方案概览（15%）
   - 每个方案的一句话定位
   - 核心设计哲学（每个方案最看重的价值是什么）
   - 典型使用场景

3. 多维度对比矩阵（40%）
   - 选择 4-6 个关键维度进行对比
   - 每个维度先定义评估标准，再逐一评估各方案
   - 使用表格可视化对比结果

4. 决策树/适用场景（20%）
   - "在什么情况下选 A？""在什么情况下选 B？"
   - 给出明确的决策逻辑（if-then 规则）
   - 混合方案的可能性

5. 风险与建议（15%）
   - 每个方案的主要风险
   - 迁移/回滚策略
   - 最终推荐及理由
```

**常用对比维度**：
- 性能（吞吐量、延迟、资源占用）
- 可靠性（容错性、数据一致性保证）
- 可维护性（复杂度、文档、社区活跃度）
- 安全性（攻击面、安全特性、审计能力）
- 成本（硬件、许可、运维人力）
- 团队适配（学习曲线、现有技术栈兼容性）

**示例**：
- 消息队列选型：Kafka vs RabbitMQ vs Redis Streams → 吞吐/延迟/一致性/运维复杂度对比 → "高吞吐日志选 Kafka，复杂路由选 RabbitMQ，简单场景选 Redis"决策树

## 演进式（Evolutionary）

**适用场景**：技术史讲解、架构演进、协议发展、设计模式演变
**核心思想**：展示技术如何随需求和约束变化而演进，让受众理解"为什么现在是这样"。

**结构框架**：

```
1. 历史背景（10%）
   - 当时的约束条件（硬件、网络、业务规模）
   - 当时面临的核心挑战
   - 已有的解决方案及其局限

2. 第一代方案（20%）
   - 设计思路和核心机制
   - 解决的主要问题
   - 暴露的新问题或局限

3. 第二代改进（25%）
   - 针对第一代问题的改进思路
   - 引入的新机制或抽象
   - 改进后的效果和新的局限

4. 现代最佳实践（30%）
   - 当前的主流方案及其设计哲学
   - 与前代的本质区别
   - 工程实践中的具体实现

5. 未来趋势与反思（15%）
   - 当前方案面临的新挑战
   - 正在探索的方向
   - 从演进史中得到的通用设计原则
```

**示例**：
- 讲解 Web 安全防御演进：从早期的明文传输 → SSL/TLS 1.0 → 心脏出血等漏洞 → TLS 1.3 的简化设计 → 后量子密码学的挑战
